# Подготовка версии 3.1 к Google Play

Дата проверки: 7 ноября 2026. Публикация в Google Play ещё не выполнена.

## Собрано

- Android: версия 3.1, versionCode 12, пакет ru.momnotes.app.
- APK для GitHub подписан прежним отладочным сертификатом для обновления версии 3.0 без удаления приложения. Это НЕ подпись для Google Play.
- `app/build/outputs/bundle/release/app-release.aab` — локальная предварительная сборка, без настроенной постоянной релизной подписи. Не загружать как готовый продукт.
- Текущее издание — `mom` (встроенные плагины включены). Для публичного выпуска отдельно выбрать `public` через `-PmomEdition=public` и проверить поведение.

## Обязательно до отправки

1. Перевести compileSdk/targetSdk на API 36. Сейчас compileSdk 35, targetSdk 34, установлен только SDK Platform 35. Официальное требование с 31 августа 2026: https://support.google.com/googleplay/android-developer/answer/11926878 . Понадобятся SDK 36 и совместимые AGP/Gradle; затем проверить изменения Android 15/16, отступы системных панелей, напоминания и фоновые службы.
2. Настроить постоянный upload key и Play App Signing. Хранить ключ и пароли вне репозитория, сделать резервную копию. Не загружать debug-сертификат. Разные сертификаты GitHub и Play не позволят напрямую обновлять одну установленную копию другой; выбрать стратегию распространения до первого выпуска.
3. Доработать удаление аккаунта. Сейчас клиент удаляет строки с совпадающим ownerId и пытается удалить связанные файлы, затем блокирует аккаунт через account.updateStatus(). Это не физическое удаление пользователя. Нужен защищённый серверный механизм удаления аккаунта или реальный процесс обработки запросов. Не помещать серверный API-ключ в приложение. Не тестировать на настоящем аккаунте или важных данных Appwrite.
4. В текущем удалении ошибки доступа к файлам 401/403 пропускаются, а файлы без ссылок не перечисляются. Полное удаление вложений этим не гарантируется. Проверить на отдельном тестовом проекте, исправить обработку ошибок и проверить права Appwrite до заявления о полном удалении данных.
5. Добавить доступный извне способ запроса удаления аккаунта и данных. Простого блокирования/деактивации недостаточно. Правила: https://support.google.com/googleplay/android-developer/answer/13327111 .
6. Заменить `ВАШ_EMAIL@example.com` в `docs/privacy.html` на реальный адрес, уточнить разработчика/оператора данных, сроки хранения и процедуру удаления; опубликовать политику по доступной HTTPS-ссылке и добавить ссылку в приложение. GitHub Pages пока не подтверждён.
7. Заполнить Data safety по фактическому сбору: email/идентификаторы, заметки, фото/файлы, данные плагинов и иные чувствительные данные в них. Сверить политику с возможностями плагинов; не обещать, что любой плагин работает только локально.
8. Проверить поддержку страниц памяти 16 КБ всеми нативными библиотеками в итоговом пакете, если они присутствуют. Проверить AAB в Play Console и на совместимом устройстве/эмуляторе; сборка сама по себе этого не доказывает.
9. Проверить и обосновать foreground service типа mediaPlayback и точные будильники. Не считать разрешение автоматически одобренным Google. Проверить напоминания, перезагрузку, отказ в разрешениях и Android 16.
10. Подготовить карточку приложения: название, описание, контакт разработчика, скриншоты и графику; заполнить возрастной рейтинг, рекламу, доступ к приложению для проверки и остальные декларации Play Console. Выполнить требуемое тестирование, если оно назначено для аккаунта разработчика.

## Проверки и ограничения

APK и переносная Windows-сборка проверяются отдельно при упаковке релиза. Подключённого Android-устройства при проверке не было. Пользовательские сценарии и удаление на живом аккаунте не проверялись. Настоящие данные Appwrite не изменялись.

Архив `sources-3.1.zip` в релизе содержит снимок исходников, использованных для сборки; не включает local.properties, сборки, журналы, ключи или данные сеансов. Автоматические архивы Source code от GitHub относятся к коммиту тега, а не обязательно к этому локальному снимку.
